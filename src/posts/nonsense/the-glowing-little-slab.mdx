>手机触屏坏了，好像整个世界都隔了一层玻璃...   ————2026-01-25


看着屏幕里闪烁的画面却没法触摸，指尖戳上去什么反应都没有。那个瞬间，好像整个世界都隔了一层玻璃... 
或者说，其实一直都是这样。我们和所谓的“世界”，和暮暮，和那些能在网上说上话的人，中间一直都隔着这层冷冰冰的玻璃。

老说年轻人喜欢追新的电子产品，甚至有些超出消费能力的去追。可对于做这行的人来说，这可能是... 某种意义上不可避免的事情。就像写交互界面，如果在潮头的我们不去观察新产品的一个动画、一个特效，不去摸摸最新的发光小板板，慢慢就会脱离那个圈子，自己做的东西就会显得落伍、粗糙。
必须买最新的 iPhone，必须用最新的 AI 模型，因为审美和工具的迭代本身就是我们的劳动工具。这就像一种被迫的进食。

有时在调用手机里的震动马达时，我会突然意识到：手机其实就是个加了块屏幕的嵌入式设备。那开发安卓 App 算不算嵌入式开发？

如果从这个角度看，移动互联网的发家史，其实就是这块“发光小板板”狠狠雷普了当时带了一堆实体按键的功能机的历史。
实体的物理按键，你做成啥样就是啥样了，没法改了；但在这块发光小板板上，你想要什么按键、什么交互，只要性能够，都能画出来。甚至可以闲得无聊写一堆回弹动画——这太神奇了，哪怕只是一个带阻尼感的下拉刷新，我无聊的时候都能玩上一整天。再加上后来苹果在板板底下塞了各种神奇的压感和震动反馈... 一个物理设备，仅仅因为打开了不同的“应用”，就变成了完全不一样的东西。

不论怎么讲，这块可以戳戳戳的发光小板板里面，好像还住了一堆人。这种感觉，可能确实挺好的。

---

最近在搞那个知乎的三方 App，加上新公司的工作，让我对着这块板板的排版渲染发了好多呆。
然后好像意识到了 App 和浏览器的一些差异。

如果只是做文档的排版渲染，浏览器和那一堆前端工具的支持比 App 强太多了。App 的布局系统相对而言会更干净一些，更专注在发光小板板上做布局和交互；而浏览器的布局系统，加上 CSS 里那些为了向后兼容堆砌的奇奇怪怪的属性，写起来有时候简直像古神低语（虽然现在一大半都放进 flex 和 grid 里，没那么那个了 x）。

但要在 App 里做点复杂的事，比如带点图表、数学公式，或者稍微长一点的富文本... 还是乖乖用 WebView 吧。最近发现 React Native 渲染文档时，文本选中居然不能跨段落... 杂鱼 RN。

不过，为了在这块发光小板板上达到极致的丝滑，有些 App 真的变成了怪物。

前几天解压了几个 RN 的 apk 包，大厂标配基本就是模板配置生成的页面，加一堆混淆加密和信息流推荐算法，外加一点原生代码。占比其实也不多。
但当我翻开 Telegram Android 的开源代码时，真的有种被震撼到难绷的感觉。

它完全不相信系统组件。抛弃了 XML，所有的 UI 全量自绘。
当你打开它的 `res/layout` 文件夹，里面几乎什么都没有。但你打开 `ChatMessageCell.java`，迎面而来的是将近 28,800 行的庞然大物。没有任何嵌套布局，所有的背景、文字、头像、回复信息... 全部通过 `Canvas` 在屏幕上手绘，位置完全靠代码在 `onMeasure` 里算出来。
为了避免 Java 的 GC 停顿，连文本测量的排版都在后台异步线程里偷偷算好；网络连接、多媒体解码甚至 SQLite 驱动全是用 C++ 写的。

这种反潮流但极致到变态的操作，让它就算跑在 500 块钱的低端安卓机上，也能有丝滑的 120 帧。

感觉发光小板板的交互模式其实也是有限的，知道要做什么，做出来了，然后再自己手绘替换组件，优化性能。看着这几万行的单文件，虽然依旧是我这辈子可能都搞不定的事情，但... 知道了它的原理，好像也不是完全无法想象的存在。

---

后来又看了一堆别的开源 App。像 scrcpy，termux，magisk，还有各种不接大厂服务器的单纯的阅读器和播放器。

看着看着，突然觉得有点无聊，不想搞了。

费那么大劲，写几万行的 C++ 和 Java，搞各种高深莫测的并发渲染、着色器和液态玻璃特效，到底是为了什么呢？
想想也是，发光小板板，终究只是用来装各种好看的东西的。

那些代码，那些 App，那些所谓的底层技术... 可能，都只是一种形式。
真正吸引我们的，永远是这块发光小板板亮起时，里面呈现的漂亮图片，是那些色色的小故事，是远在另一个城市的暮暮发来的一条消息，是那些让我们觉得不那么孤独的、虚假却又无比真诚的连接。

时间过去好多。
今天也什么都不想做了，阿巴阿巴，睡大觉。
